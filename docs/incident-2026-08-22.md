# Incident: 2026-08-22 — cross-flavour 型混合による false-positive `divergent`

## 事実

- `meta_check_coherence("seed_kernel", detail=true)` が **常に `divergent`** を返していた
- record_count は両側 1,677 で一致 (drift ゼロ)、実データ乖離なし
- 唯一の disagreement: `latest_diff` が `"2026-08-19T00:00:00Z"` (timestamp)
  と `"resilient-knowledge-recovery"` (id 文字列) を突き合わせ、常に「differs」
- 藤本さんが `detail=true` の中身を目視して発見

## 何が問題だったか

「ずれていた」ではない。**「ずれの検出装置が、型の違うものを比較して常にずれと呼んでいた」**。
2026-08-19 incident で組んだ検出装置そのものが false-positive を発していた状態。

### 直接原因

`src/rei_meta_mcp/fingerprint.py::fingerprints_agree` L123-124 (pre-fix):

```python
a_latest = a.get("latest_id") or a.get("latest_timestamp")
b_latest = b.get("latest_id") or b.get("latest_timestamp")
if a_latest is not None and b_latest is not None:
    if a_latest != b_latest:
        return False, "latest identifier differs"
```

`or` fallback で `latest_id` (partial flavour = 任意識別子文字列) と
`latest_timestamp` (full flavour = ISO-8601 datetime 文字列) を **同じ slot に
落として `!=` 比較**。この 2 つは値空間が異なるので、実データが同一でも常に differ。

`src/rei_meta_mcp/coherence.py` L177-183 の divergence 出力にも同型 pattern
(`latest_diff` merged key)。fix 対象は 2 箇所。

## 修正 — `fingerprint_canonical`

`fingerprint_canonical(fp)` を新規追加。fingerprint dict を型保持したまま
canonical view に変換 (`latest_id` と `latest_timestamp` を別 slot で保持、
片方 flavour にしか無い field はもう片方で `None`)。

比較 rule:
- record_count: 常に (両 flavour が持つ)
- content_hash: full × full のみ
- latest_timestamp: full × full のみ
- latest_id: partial × partial のみ
- categories_hash: partial × partial のみ
- **cross-flavour (full × partial)**: record_count のみ

cross-flavour で latest_id と latest_timestamp を比較しないのは、比較材料が無い
= sound な silence。「partial 側は full 側の content を保証しない」= adapter を
上げる話であって、比較を厳しくする話ではない。

`coherence.py` の divergence 出力も `latest_diff` merged key を廃止し、
`latest_id_diff` + `latest_timestamp_diff` の typed 2 key に分離。

## Before / after evidence

同一 pair (full{count=1677, latest_timestamp='2026-08-19T00:00:00Z'} ×
partial{count=1677, latest_id='resilient-knowledge-recovery'}):

| logic | agree | reason |
|---|---|---|
| OLD | False | `latest identifier differs` ← false-positive |
| NEW | True | `agree on: record_count` ← correct |

実 drift (count 1677 vs 1675) sanity:

| logic | agree | reason |
|---|---|---|
| NEW | False | `record_count differs` ← 実 bug 検出 preserved |

## スコープ分離 — `theory_canonical(T)` は別関数

`fingerprint_canonical` は fingerprint 比較用の canonical view であって、
`dfumt-content-address-retrieval` が要求している **`theory_canonical(T)` (任意
理論表現の CID 計算用) ではない**。同名にすると 「hypothesis 依存が埋まった」
と誤読される (siren-family pattern の逆)。→ 名前を別関数として切り、
`theory_canonical` は 未実装 = 「見える負債」として維持。

module docstring に明示。

## N=1 の恩恵

fix 時点で registry object は `seed_kernel` 1 件のみ。fingerprint 契約を触る
コストが最小。object 数が増えてから同じ fix を入れると、全 source の adapter
出力の shape 契約を書き換えることになる。**「N=1 の今が最安期」** の
operational 実証。

## テストで固定した挙動

`tests/test_fingerprint_canonical.py` に 11 test:

1. **決定性 floor** (3 test): `serialize_fingerprint_canonical(fp)` が同入力で
   byte-equal (`sort_keys=True` + no whitespace + UTF-8)
2. **型分離** (2 test): full flavour は full field のみ、partial flavour は
   partial field のみ露出、他方 flavour の field は None
3. **2026-08-22 bug 再現** (3 test): 直接 pair + 順序反転 + 実 drift sanity
4. **partial × partial 保持** (2 test): latest_id 比較が生きている
5. **full × full 保持** (1 test): content_hash 権威が生きている

このテスト群が落ちる日、この incident の教訓が回帰している。

## 事後 discipline

- fingerprint 比較で新 field を追加する時は **常に typed field で追加**
  ('latest_X' merged fallback は禁止)
- adapter 追加時は flavour を明示、cross-flavour 比較 rule を意識
- `fingerprint_canonical` の byte-equal floor test を維持 (決定性が崩れると
  ledger や差分器が同型に崩れる)
